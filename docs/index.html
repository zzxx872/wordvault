📖 三条可行路径 & 技术边界（必读）
先纠正一个常见误解：iPhone 的「设置 › 通用 › 键盘 › 文本替换」页面里没有「导入短语」按钮。 批量导入 .plist 是 macOS 独有功能（把文件拖进「系统设置 › 键盘 › 文本替换」列表）。 iOS 侧只能逐条手动新建；数据靠 iCloud 从 Mac 单向同步过来。

路径 A · Mac 中转（最稳，推荐）

  1. 在本工具里整理好词条，点「导出 iOS 文本替换 .plist」
  2. 把 .plist 传到 Mac（AirDrop / 微信文件传输 / iCloud 云盘）
  3. Mac：系统设置 › 键盘 › 文本替换，把文件直接拖进列表
  4. 确认 Mac 与 iPhone 登录同一 Apple ID，并已开启 iCloud 同步（设置 › 你的名字 › iCloud › iCloud 云盘）
  5. 等几分钟，iPhone 上自动出现。条目多时同步会慢，属正常现象

路径 B · 无 Mac，iPhone 单机（用逐条录入助手）

iPhone 无法批量写入，只能一条条建。本工具的「逐条录入助手」把每条拆成「复制短语 → 粘贴 → 复制输入码 → 粘贴 → 保存」的流水线， 自动记住进度，比手工编辑快得多。适合精简到 50~200 条的核心词库。

提速技巧：把输入码设计得规律一点（比如全部带同一前缀），输入码那一步直接手打，能省一半时间。

路径 C · 搜狗输入法云同步（无 Mac 时的唯一「真·批量」方案）

  1. Windows 装搜狗输入法（你现在这台电脑就行）
  2. 本工具点「搜狗 PC 格式」导出 .txt
  3. 搜狗：状态栏图标 → 设置属性 › 高级 › 自定义短语设置 › 导入，选中文件
    格式为 缩写,位置=短语（如 dz,1=北京市朝阳区…），位置填 1 即可
  4. 登录搜狗账号并开启同步
  5. iPhone 装「搜狗输入法」，开启「完全访问」，登录同一搜狗账号 → 词库自动同步过来
这是没有 Mac 也能真正批量写入的唯一路径。代价：放弃系统输入法「纯本地、不上传」的特性，且需要开完全访问权限。

另一条备选：搜狗 iOS 版支持「系统设置 › 搜狗输入法 › 词库与短语 › 自定义短语 › 从文件导入」， 本工具的「搜狗 iOS (.bdi)」导出即为此准备（格式 缩写=短语、UTF-16 LE 编码）。此格式各家版本变动较多，建议先导 2~3 条试一下。

关于「词库」的三层理解

  • ① 自定义短语 / 文本替换 — 唯一可批量操作的层，就是本工具处理的层
  • ② 用户词典（自动学习词、防误纠错） — 没有任何公开 API，也导不进去。只能靠日常输入让系统慢慢学，或在 设置 › 通用 › 传输或还原 iPhone › 还原 › 还原键盘词典 重置
  • ③ 第三方输入法词库 — 各家自己的格式，各 App 内导入
所以「增加和管理系统输入法词库」这件事，能程序化操作的只有 ①。 好在 ① 恰好就是提升输入效率最有效的那部分——长文本模板（地址、发票信息、工作话术、邮箱签名）。

输入码设计三条铁律

  • 别用太短的纯字母：设了 bj → 北京，那你正常想打「不见」的时候就废了。用 /bj、;bj 这类带前缀的
  • 长度 2~4 个字符最优：超过 5 个字符，还不如直接打字
  • 只放长文本：一个 2 个字的词不值得占一个输入码。词库总量建议控制在 300~1000 条以内

为什么「城市库 / 通讯录」其实收益很低

系统拼音输入法本来就有全国城市词库；通讯录里的名字系统会自动从「通讯录」学习。 把 585 个城市批量做成文本替换，除了挤占输入码空间、拖慢同步，几乎没有收益。 建议把词库重心放在你反复手打的长内容上。

💻 没有 Mac，怎么把这个工具用起来？（含 GitHub Actions 云编译的判断）
先说一个容易被绕进去的坑：用 GitHub Actions 云编译出 iOS App 装到手机上， 并不能解决批量导入的问题。因为 iOS 系统根本没开放「写文本替换」的 API—— 你写一个 App 出来，它能做的事和这个网页一模一样，甚至更少。

iOS App 到底能带来什么？（诚实版）

  • 不能批量写入文本替换 — 没有这个 API，苹果没给
  • 不能写用户词典（自动学习词）— 同样没有 API
  • 唯一的增量是「自定义键盘扩展」——但那就等于自己写一个输入法， 工作量是现在的一百倍，而且还得开「完全访问」。真要走到那一步，不如直接用搜狗。

所以：没有 Mac 的情况下，别把精力投在 iOS App 上。

如果还是想把 App 编译出来（技术上可行）

  1. GitHub Actions 的 macos-15 runner 自带 Xcode，公开仓库免费不限时长
  2. 用 xcodebuild 关掉签名编译出 .app，打成未签名 .ipa 上传为 Artifact
  3. Windows 上用 AltStore 或 Sideloadly（都有 Windows 版）+ 你的 Apple ID 重签名后安装
  4. 免费 Apple ID 签名 7 天过期，最多 3 个 App，过期要重装
  5. 想摆脱 7 天限制，唯一正规途径是 $99/年 开发者账号走 TestFlight（90 天有效）

仓库里已备好 .github/workflows/build-unsigned-ipa.yml，推到 GitHub 就能跑。但请先想清楚值不值。

推荐路线（按性价比排序）

  1. 把这个工具部署到 GitHub Pages，iPhone 上当 App 用 — 免费、HTTPS、不用签名、不用续期。 本工具已放在仓库的 docs/ 目录，Pages 分支部署开箱即用； 然后 iPhone Safari 打开 → 分享 → 「添加到主屏幕」，就是个离线可用的图标。
  2. 搜狗 Windows + 账号云同步 — 见上一条「路径 C」，无 Mac 时唯一能真正批量写入的办法
  3. 借一台 Mac 用 10 分钟 — 拖入 plist，iCloud 同步到 iPhone，一劳永逸（同事/朋友/网咖都行）
  4. 逐条录入助手 — 以上都不行时的兜底，精简到 50~200 条最现实

部署到 GitHub Pages 的具体操作

  1. 仓库 Settings › Pages › Source 选 Deploy from a branch， Branch 选 main + /docs，保存
  2. 等 1 分钟，访问 https://zzxx872.github.io/wordvault/
  3. iPhone Safari 打开该网址 → 分享 → 添加到主屏幕
仓库里没有用 Actions 部署 Pages，是故意的：分支部署零配置、不会因为 workflow 权限失败。 如果你更习惯 Actions，仓库里也留了 .github/workflows/pages.yml（需把 Source 改成 GitHub Actions）。

提醒：词条数据存在浏览器本地（localStorage）。换浏览器、清缓存会丢，记得偶尔点一下「JSON 备份」。 如果以后想多设备同步，可以再考虑接入一个云端存储，但那样就要重新权衡隐私问题了。
批量粘贴导入

每行一条，自动识别这几种写法：
短语 ｜ 短语,输入码 ｜ 输入码=短语 ｜ 短语　输入码（Tab 分隔）
Markdown 表格（| 输入码 | 短语 |）也能直接粘。

逐条录入助手
① 短语 — 粘贴到「短语」栏
② 输入码 — 粘贴到「输入码」栏
快速模式：输入码有规律（前缀 + 拼音首字母），直接手打更快，不用复制。
操作流程
1. 点上面两个按钮分别复制（变绿即成功）
2. 打开 设置 › 通用 › 键盘 › 文本替换
3. 点右上角 ＋，长按粘贴短语，再粘贴输入码
4. 点 存储，返回这里点「完成，下一条」
跳转失败属正常，手动打开设置即可
